# Root-Cause Backlog — recurring issues to fix at the source

> A living register of **issue patterns that keep coming back**. Each row is a recurring symptom, its suspected root cause, and the work that would kill it for good — so the team fixes the *cause* once instead of re-working the *symptom* every time.
>
> **Pairs with the [alert coverage ledger](../products/opcp-core/misc/first-responder/alerts/coverage-ledger.md):** the ledger tracks *can we detect it?*; this backlog tracks *why does it keep happening, and what removes it?* Both are First-Responder instruments — the second time an issue is seen, it should already be here (FR Principle 3).
>
> **Maintained by the [`/learning`](../.claude/skills/learning/SKILL.md) skill** (§3): every working/debugging session that hits a recurring symptom adds an occurrence or a new row. **Passive index — the Copilot maintains it; a human executes every fix.**

## How to read this

- **Status** — the lifecycle of the *root cause*, not the symptom:
  - 🔴 **open** — recurs, no mitigation and no fix.
  - 🟡 **mitigated** — a runbook makes it survivable (symptom handled fast), but the root cause is still live and it will recur.
  - 🟢 **fixed** — root cause removed. Row kept for history; new occurrences should be rare and reopen it.
- **Signature** — how to recognise it fast (error string, failing component, alert name) so the next responder matches it in seconds.
- **Suspected root cause** — labelled `[verified]` (proven in a session against logs/code/CLI) or `[inference]` (best current hypothesis, not yet proven). Never promote inference to fact without evidence.
- **Occurrences** — a running count + dated links to the sessions / tickets where it bit. Incident specifics (nodes, timestamps) live in those links, **not** in the pattern row.
- **Mitigation** — the symptom runbook that gets you out of trouble *now*.
- **Root-cause fix** — the BAU/SOV ticket (or open-question, if the cause is still unknown) that addresses the source. **A pattern at ≥2 occurrences should have one** — that is the whole point of this backlog: it must *generate* remediation work.

## How entries get added

Don't hand-curate this — run [`/learning`](../.claude/skills/learning/SKILL.md) at the end of a session. Its §3 step:

1. **Greps** this file for the symptom's signature.
2. **Matches** → adds a dated occurrence + bumps the count; **or new** → adds a row.
3. **At ≥2 occurrences or a known cause** → proposes a root-cause fix ticket and links it here.

A row's *root-cause fix* graduating to done flips its status to 🟢 — but keep the row, so the history of "this used to bite us" survives.
